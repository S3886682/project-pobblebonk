================================================================================
  FROGFINDER  |  DATA MANAGEMENT INFORMATION
================================================================================

The app uses two storage layers: on-device local storage (always active) and
an optional Supabase cloud database for cross-device sync (scaffolded).


================================================================================
  1. LOCAL ON-DEVICE STORAGE  [PRIMARY — ALWAYS ACTIVE]
================================================================================

  A. JSON Flat-File  (sightings)
  --------------------------------
  Type:       Plain JSON file via expo-file-system
  Library:    expo-file-system (legacy API)  v19.0.21
  File path:  {FileSystem.documentDirectory}sightings.json
              This resolves to the app's sandboxed documents directory, e.g.:
                iOS:     /var/mobile/Containers/Data/.../Documents/sightings.json
                Android: /data/data/com.frogfinder/files/sightings.json
  Schema:     JSON array of sighting objects:
                id           string   (Unix timestamp as string)
                species      string   (common name, e.g. "Pobblebonk")
                confidence   number   (0.0 – 1.0)
                alternatives array    (up to 4 runner-up species + confidence)
                date         string   (ISO 8601)
                location     object   { lat, lng, locality } or null
  Managed by: FrogFinder/services/sightingsService.js
  Notes:      This is the live data store used by the current app build.
              Persists across app restarts. Cleared only via "Delete" in the
              Sightings screen or sightingsService.clearAll().


  B. SQLite Database  (scaffolded — not active in current build)
  ----------------------------------------------------------------
  Type:       SQLite (embedded relational database)
  Library:    expo-sqlite  (bundled with Expo SDK 54)
  File name:  frogfinder.db
              Stored in the app's documents directory alongside sightings.json
  Version:    SQLite 3 (version managed by the device OS/Expo runtime)
  Connection: Local file — no host, port, or credentials required
  Schema:
    TABLE sightings
      id               INTEGER  PRIMARY KEY AUTOINCREMENT
      species_name     TEXT     NOT NULL
      scientific_name  TEXT
      confidence       REAL
      latitude         REAL
      longitude        REAL
      recorded_at      TIMESTAMP  DEFAULT CURRENT_TIMESTAMP
      audio_url        TEXT
      spectrogram_url  TEXT
      cloud_id         TEXT       (foreign key to Supabase row id after sync)

    INDEXES
      idx_recorded_at   ON sightings(recorded_at)
      idx_species_name  ON sightings(species_name)

  Managed by: FrogFinder/config/database.js
  Notes:      Schema is initialised by initializeDatabase() but this path is
              not wired into the active app flow. Intended for a future
              migration from the JSON flat-file store.


  C. Bundled Static Data  (read-only, ships with the app)
  --------------------------------------------------------
  Species details:
    File:   FrogFinder/assets/data/speciesDetails.json
    Format: JSON array — name, scientific_name, description, callDescription,
            habitat, size, conservationStatus, image (asset key)
    Used by: AboutScreen (species browser), ClassifyScreen (result detail modal)

  ML Model:
    File:   FrogFinder/services/svm_model.json
    Format: JSON — SVM support vectors, dual coefficients, Platt calibration
            parameters, mel filterbank weights, scaler mean/scale
    Size:   ~several MB (included in app bundle)
    Notes:  Generated by ModelTraining/export_model_json.py.
            Never written to at runtime — treat as immutable.


================================================================================
  2. CLOUD DATABASE  [OPTIONAL — requires environment variables to activate]
================================================================================

  Provider:       Supabase
  Database type:  PostgreSQL
  Postgres ver:   Managed by Supabase (currently PostgreSQL 15.x)
  Hosting:        Supabase cloud (AWS infrastructure, ap-southeast-2 region
                  unless project was created in a different region)

  Connection address:
    The project URL follows the pattern:
      https://<project-ref>.supabase.co
    The exact URL is stored in the environment variable:
      REACT_APP_SUPABASE_URL

  Authentication:
    Method:   Anonymous (anon) key — Row Level Security (RLS) enforced by
              Supabase policy on the database side
    Key env:  REACT_APP_SUPABASE_ANON_KEY
    Client:   @supabase/supabase-js  (version from package.json)

  To activate cloud sync, create a .env file in FrogFinder/ containing:
    REACT_APP_SUPABASE_URL=https://<project-ref>.supabase.co
    REACT_APP_SUPABASE_ANON_KEY=<anon-key-from-supabase-dashboard>

  These credentials are available in the Supabase project dashboard under:
    Project Settings > API > Project URL & Project API Keys

  Client setup:   FrogFinder/config/supabase.js
  Sync logic:     FrogFinder/services/uploadService.js

  Cloud schema (mirrors the SQLite schema above):
    TABLE sightings
      id               uuid / serial   PRIMARY KEY (Supabase default)
      species_name     text            NOT NULL
      scientific_name  text
      confidence       float
      latitude         float
      longitude        float
      recorded_at      timestamptz     DEFAULT now()
      audio_url        text            (public URL to Supabase Storage bucket)
      spectrogram_url  text            (public URL to Supabase Storage bucket)

  Supabase Storage buckets (for audio/spectrogram files):
    Managed via uploadAudioToSupabase() and uploadSpectrogramToSupabase()
    in FrogFinder/config/supabase.js

  Current status:
    Cloud sync is scaffolded but NOT currently integrated into the active
    app flow. The sightingsService.js (JSON flat-file) is the live store.
    uploadService.js exists and is functional but is not called from any
    screen. To enable, wire uploadService.syncSightings() into the app.
